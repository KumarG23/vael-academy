## Delivered scope (partial keybinding support)

- **Journal → System → Keyboard Controls** (appended last row, so every existing System row index is unchanged). A themed modal page lists Up/Down/Left/Right/Confirm/Cancel with their **default keys (always active)** next to an **additional key** column (`none` when unset), per-row **Change**/**Clear** buttons (←/→ choose, Enter presses; Delete also clears), **Restore Defaults (remove additional keys)** and **Back to System**.
- Change captures one **fresh, non-echo, unmodified keyboard press**. Esc cancels the capture without assigning or closing the editor/Journal. The capture is consumed before it is applied. While open, the editor consumes every key event in `_input`, so the captured key's echo/release can't reach the Journal, ChoiceMenu, room map, room editor or exploration. After assignment the new key immediately navigates the editor.
- Rejections show a reason and ask for another key; the prior binding stays as it was. Rejected inputs: any shipped key of any InputMap action (the six core actions, Godot `ui_*` built-ins such as Tab/Home/PageUp/Backspace), every key production code reads directly by keycode (J, M, backtick, T/Tab, H, PageUp/Down, R, Space, Enter/KP Enter, Esc, arrows/W/S, campus-editor and Dev Jump pilot keys), another action's additional key, modifier-only and lock keys, chords (Shift/Ctrl/Alt/Meta held), and mouse/controller input. Re-choosing an action's own key is allowed.
- `KeyboardPreferences` autoload (registered via `ProjectSettings` from a headless script, not by hand-editing `project.godot`). It snapshots the shipped InputMap at startup, then adds one `InputEventKey` per chosen key to the existing core action and its matching built-in alias (`cursor_up`↔`ui_up`, … `cursor_confirm`↔`ui_accept`, `cursor_cancel`↔`ui_cancel`). Shipped events are never removed. There is no extra resolver, no input-injection loop and no per-frame settings IO.
- Consumers: battle cursor (held repeat), battle/castle ChoiceMenus, Journal, house choice, quiz, fishing and the exchange skip already read actions, so they need no change. Castle walking (`ui_*` axis), interaction (`ui_accept`) and the exploration system menu (`ui_cancel`, the same meaning as Esc there) work through the aliases. Two hard-coded consumers were adapted: **dialogue** (an additional Up/Down/Confirm reaches the same choice/advance branch as the shipped keys) and the **room map/travel** modal (an additional Up/Down/Confirm/Cancel acts like ↑/↓/Enter/Esc, Up/Down with arrow-style repeat). Other keys keep their meaning: Space fast-forward, Esc skip, PageUp/Down cycling, T/Tab end turn, H danger zones, J/M and editor keys. A custom Cancel during an exchange follows the existing `cursor_cancel` skip.
- Persistence: `[keyboard]` section of installation-local `user://settings.cfg`, stored as readable key names (`up = "I"`). Loaded in autoload `_ready`, before the first scene input. Missing, unreadable, wrong-type, unknown, chord, reserved or duplicated values mean no additional key, so they can't disable defaults or activate a conflicting command, and reading never writes. Writes keep every other section of a readable file, replace only `[keyboard]`, and use temp-file + rename. A failed write keeps the live binding for the session and shows "Not saved (…) — applies this session only." A readable file's bytes are untouched on failure; an unreadable file is reported and left alone. A later ordinary change retries and succeeds. New Game, slot load and Dev Jump don't touch the preferences, and there is no campaign/save schema change.

Not delivered (deliberately): remapping any other command, replacing or removing shipped keys, controller support (a §1 non-goal), more than one additional key per action, or mouse capture in the editor.

**Observations and limits**
- The battle cursor polls held state once per frame. On this slow software renderer, near-instant synthetic taps were sometimes missed for **both** shipped arrows (4 taps → 1 move) and custom keys (4 taps → 0), while 150 ms holds were reliable for both. This is existing behavior, not introduced here; ordinary human key presses are longer.
- In the exchange, Kael was defeated partway through and P was pressed near its end. The capture shows the field back at idle with no stray menu or selection, but it can't prove how much presentation P skipped. The custom-Cancel skip and its identical outcome are asserted by `test_keyboard_controls_battle.gd`.
- The editor title sits under the top-left corner ornament at both sizes, the same placement as the existing Journal title. The Journal footer's left end also runs under the bottom-left ornament on main. Both are left unchanged to avoid shared Journal edits; this is a presentation note, not a functional defect.
- Not exercised graphically: travel to another room by custom Confirm (the fixture had no second visited room; covered in the automated tests), a real write failure (automated) and mouse capture rejection (automated).
- Bounded Dev Jump fixture. No whole-year replay and no Neal taste/visual approval are claimed.
